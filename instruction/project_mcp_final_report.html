1. 项目定位与最终架构

面向中文旅游场景的智能旅游助手：以 Model Context Protocol 为工具总线、LangGraph 为编排引擎，串联「意图识别 → 路由决策 → 工具调用 → 结果整合」，对外提供 CLI（main.py）、FastAPI/SSE（frontend_api.py）与 MCP 服务三种入口。

实测技术栈：Python 3.12.12 · FastMCP 3.2.4 · LangGraph 1.1.10 · langchain-openai 1.1.11 · langchain-chroma 1.1.0 · chromadb 1.5.5 · FastAPI 0.136.0 · pydantic 2.13.3 · aiohttp / tenacity / httpx-sse。17 项关键依赖在 myenv312 中全部存在。

1.1 最终分层架构

入口层     main.py(CLI) | frontend_api.py(FastAPI/SSE) | start_mcp.bat + server.py(MCP 服务)
   ↓
编排层     workflow/graph.py(StateGraph) + state.py(WorkflowState / AgentResponse)
   ↓
智能体层   intent_recognizer | search_agent | route_agent | travel_agent | rag_agent
   ↓
集成层     integration/tool_adapter.py(MCPAdapter 单例，引用计数 + call_tool 统一入口)
           protocol/client.py(同进程直连 / Streamable HTTP 双模式)
   ↓
协议层     protocol/server.py：8 tools / 2 prompts / 1 resource
   ↓
能力层     tool_amap/(高德 + 12306) | tool_rag/(本地 bge-m3 + Chroma) | core/(LLM/日志) | config/(Settings)
相对初始架构的三处结构性变化
  • 删掉第二条 MCP 链路：RouteAgent / TravelAgent 不再自建 SSE，全部注入同一个 MCPAdapter；建连/断连各恰好 1 次。
  • 新增 RAG 服务层：rag_service.py 单例（懒加载、线程安全、优雅降级）→ TravelRAG → Chroma 持久化，由 4 个 MCP 工具暴露。
  • 远程传输统一：默认同进程；MCP_HTTP_URL 非空时切到 transport="streamable-http"，端点 /mcp。

1.2 主链路数据流

用户输入 → intent_recognition(LLM，标签行结构化解析) → 条件路由
  ├ chat   → chat_response(LLM) → END
  ├ search → Search(Tavily + LLM 攻略)
  │          → rag 节点【先检索历史知识 → 再把本篇攻略入库】
  │          → 命中片段原文直出、追加到 final_output → END
  ├ route  → RouteAgent → MCPAdapter.call_tool('route_planning')
  │          → 高德 + 12306（失败诚实降级为「暂不可用」+ 距离估算） → END
  └ travel → TravelAgent = Search + RouteAgent + LLM 整合
             → 质量字段透传 + 代码强制免责声明 → END
                 ↓
        final_output → _clean_final_output() → CLI / /chat / /chat/stream

5.3 数据真实性机制（本次治理的核心原则）

  • 质量分级：所有路线结果带 data_quality = real | partial | estimated | failed 与 is_realtime、warnings；估算值不再置 success=True。
  • 无数据时不编造：12306 查不到车次 → 「暂不可用（请查询铁路 12306 官方）」；火车段按距离估算（250km/h + 40min 缓冲）并显式标注「非实时」。
  • 免责声明由代码追加：travel 输出末尾强制追加「请勿据此购票，请以铁路12306或航司官网为准」，不依赖 LLM 自觉。
  • 字段贯通：route_agent → travel_agent → WorkflowState → /chat 响应与 done 事件，前端可直接渲染「实时 / 估算 / 降级」徽标（UI 尚未实现）。
  • 质检硬门槛：攻略含伪造/占位痕迹、缺可核查来源、章节不足 5、字数 ≤800 任一即 passed=false。
  • RAG 原文直出：检索片段不经 LLM 改写，标注「非实时数据，仅供参考」，避免二次编造。
